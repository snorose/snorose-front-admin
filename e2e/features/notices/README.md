# 공지 실제 API E2E 검증

```bash
npx playwright test e2e/features/notices/notices.read.spec.ts --project=dev-read
```

기존 `dev-auth`로 로그인한 뒤 실제 개발 API `GET /v1/admin/notices?page=0`부터 `hasNext=false`까지 조회합니다. 네트워크 모킹과 서버 데이터 작성·수정·삭제는 사용하지 않습니다.

- TC-ADM-NOTICE-001: API 항목·개수·서버 순서·10개 페이지네이션·수정 비활성화
- TC-ADM-NOTICE-002: `NEW` 즉시 적용·검색 전 텍스트 미적용·Enter로 다른 페이지의 제목 검색
- TC-ADM-NOTICE-003: 공통 작성자 드롭다운의 ‘작성한 공지글’ 선택·동일 작성자 재선택 시 입력 동기화·닉네임 검색과 작성 화면 이동
- TC-ADM-NOTICE-008: 날짜 범위와 조회수 정렬 즉시 조합·날짜 해제 후 정렬 유지·미적용 검색어 보존
- TC-ADM-NOTICE-009: 게시판·하위 게시판 드롭다운 전환·단일 게시판의 하위 선택 비활성화·대분류 변경 시 이전 하위 선택 해제

로그인 setup을 포함해 조회 실행은 총 6개 테스트입니다.

조회 API가 `page`만 받으므로 화면의 검색·필터는 모든 페이지를 수집한 뒤 적용합니다. 작성자 ID·작성일·예약 일시·카테고리·첨부가 목록 응답에 없어 샘플 값으로 보완하지 않습니다. 날짜 필터는 마지막 수정일 기준이며, 작성자 상세 조회와 기존 공지 수정은 아직 연동하지 않았습니다.

검색 영역은 공통 `SectionTitle`, 목록 제목과 건수는 `SectionTitleWithCount`를 사용합니다. 게시판·상태·구분·정렬·날짜 조건은 선택 즉시 함께 적용합니다. 검색어·작성자 텍스트는 검색 버튼 또는 Enter로 적용하며, 선택형 필터를 바꿔도 미적용 텍스트를 유지합니다. 조건 적용 시 첫 페이지로 이동하고, 초기화는 적용된 조건과 편집 중인 값을 모두 지웁니다. 작성자 드롭다운의 ‘작성한 공지글’은 바로 적용하고 검색창도 동기화합니다. 날짜와 정렬의 조합, 한글 조합 중 Enter·미적용 입력을 남긴 페이지 이동·URL 이동의 동기화는 화면 통합 테스트에서 검증합니다.

## 실제 작성 검증

```bash
E2E_NOTICE_CREATE=1 npx playwright test e2e/features/notices --project=dev-read --project=dev-write
```

TC-ADM-NOTICE-004는 실제 화면에서 이미지 2개를 첨부하고 순서를 변경한 뒤 임시저장합니다. 생성 API 201, 실제 S3 PUT 성공, 새로고침 후 목록 유지와 유저단 비공개 상태를 확인합니다. 생성한 ID는 각 테스트 리포트의 `created-notice.json`에 기록합니다. 업로드·assertion 실패 시에도 확인된 ID를 남기며, 응답이 유실된 경우에는 고유 제목으로 등록 여부를 확인할 수 있습니다. 토큰·업로드 서명 URL은 정리 기록에 포함하지 않습니다.

Playwright의 E2E 전용 서버는 API와 S3가 허용하는 `http://localhost:3000`에서 실행합니다. 일반 개발 서버의 `npm run dev`는 기존 5173 포트를 유지합니다. 5173에서 직접 첨부를 확인하려면 S3 CORS에 `http://localhost:5173` Origin과 PUT·content-type 허용을 추가해야 합니다. 프록시나 브라우저 보안 해제는 사용하지 않습니다.

**어드민 공지 삭제 API가 없어 생성 데이터는 백엔드 정리가 필요합니다.** 기본 `dev-write` 실행에서는 생성 TC를 건너뜁니다. `E2E_NOTICE_CREATE=1`만 지정하면 임시저장 TC 004를 실행하며, 실제 공개를 동반하는 TC 005~007은 아래의 추가 플래그가 필요합니다. 공지 생성 TC는 CI를 포함해 자동 재시도를 하지 않습니다.

새 공지는 `POST /v1/admin/notices` 이후 받은 presigned URL에 파일 원본을 PUT합니다. 즉시 게시한 첨부 글은 유저단과 같은 썸네일 API도 호출합니다. 임시저장·예약 글은 비공개라 해당 썸네일 API가 허용하지 않으므로 호출하지 않습니다.

로딩·빈 목록·중간 페이지 실패·재조회와 원래 에디터 UI 회귀는 `src/pages/notices`의 통합 테스트에서 별도로 검증합니다. 공통 실행 환경과 계정 설정은 [Playwright 가이드](../../../docs/playwright-e2e-guide.md)를 참고합니다.

저장 응답 대기·파일 업로드 중·업로드 실패 후 재시도 대기 상태에서는 첨부의 드래그·방향키·이동 버튼·삭제를 잠급니다. 잠금 전에 시작한 드래그의 지연 drop과 잠금 해제 후 남은 이전 drag 데이터도 컴포넌트·통합 테스트에서 검증합니다. 재시도 시 화면과 최초 POST의 첨부 순서를 유지하고, 새 POST 없이 실패한 파일만 다시 전송하는지도 확인합니다.

생성 요청의 응답 유실·타임아웃·5xx는 서버에 이미 저장되었을 수 있어 같은 화면에서 재생성하지 않습니다. 작성 내용을 유지한 채 새 창의 목록에서 등록 여부를 확인하도록 안내합니다. 명확한 입력·권한 거절 응답은 입력을 수정해 다시 저장할 수 있습니다. 생성 ID가 확인된 뒤 업로드가 실패했다면 실패한 첨부만 재시도합니다. 업로드 URL 만료·접근 거절은 공지 ID와 함께 문의하도록 안내하며, URL 재발급 API가 없어 자동 복구하지 않습니다.

첨부를 삭제하거나 작성 화면을 나가면 미리보기 객체 URL을 해제합니다. 순서를 이동할 때는 기존 미리보기를 유지합니다. 이 수명과 응답 유실 시 중복 생성 방지는 목록 API 통합 테스트에서 확인합니다.

## 즉시 공개·예약 자동 공개·동영상 TC

```bash
E2E_NOTICE_CREATE=1 E2E_NOTICE_PUBLISH=1 npx playwright test e2e/features/notices --project=dev-read --project=dev-write
```

이 명령은 조회 TC 5개·작성 TC 4개와 로그인 setup을 실행합니다. 실제 개발 서버의 공지사항 게시판에 임시저장 1개와 공개되는 공지 3개를 생성합니다. 예약 TC의 데이터도 예약 시각이 되면 공개됩니다. 제목은 실행마다 고유한 `[E2E:NOTICE:...]` 접두사를 사용하고 본문에 QA용 글임을 명시합니다. 전용 QA 계정으로 실행하고, 리포트의 생성 ID를 기준으로 백엔드에서 정리합니다. 테스트에 실패해도 이미 생성된 글이나 예약은 유지될 수 있습니다.

| TC                | 자동 검증 범위                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| TC-ADM-NOTICE-004 | 이미지 2개 첨부·순서 변경·임시저장·S3 PUT·새로고침 후 유지·유저단 목록/상세 비공개                                             |
| TC-ADM-NOTICE-005 | 이미지 순서를 바꿔 즉시 게시·실제 PUT·썸네일 API 202·유저단 상세의 첨부 순서·CDN 이미지 디코딩·첫 첨부로 생성된 썸네일         |
| TC-ADM-NOTICE-006 | UI로 한국 시간 예약·예약 전 목록/상세 비공개·서버 스케줄러의 PUBLISHED 전환·예약 시각 이후 유저단 노출·관리자 목록의 게시 상태 |
| TC-ADM-NOTICE-007 | 실제 H.264 MP4의 로컬 미리보기·VIDEO 요청·실제 PUT·유저단 API의 CDN 동영상 브라우저 재생·생성된 썸네일 디코딩                  |

예약은 최소 90초 이후의 분 경계로 설정하고, 고정 sleep 대신 상태를 반복 조회합니다. 예약 시각 이후 최대 120초 동안 스케줄러 반영을 기다리며, 미반영·조기 공개는 실패로 처리합니다. 비동기 썸네일도 최대 90초 동안 반복 조회하고, 원본 URL 대체만으로는 생성 성공으로 판정하지 않습니다. 전체 실행은 예약 대기로 수 분이 걸릴 수 있습니다.

하나만 실행하려면 위 명령 뒤에 `--grep TC-ADM-NOTICE-006`처럼 TC 번호를 붙입니다. 기본 생성 플래그와 공개 플래그를 모두 지정해야 합니다.

검증 경계는 **어드민 작성 UI → 실제 dev API/S3 → 유저단 API/CDN → 브라우저 미디어 디코딩·재생**입니다. `snorose-front` 앱의 전체 상세 화면과 모바일 첨부 뷰어를 직접 실행하는 테스트는 포함하지 않습니다. 예약 TC는 첨부 없는 글로 자동 공개를 검증하며, 예약 첨부의 썸네일 정책은 별도 범위입니다. 파일 정책의 모든 크기·포맷 조합이나 이미지/동영상의 시각적 품질까지 보장하지 않습니다.

조회·작성 도우미는 기존 다른 기능과 같은 `notices.api.ts`, `notices.page.ts`, `notices.fixture.ts` 구조를 사용합니다. 영상 파일의 생성 방식은 [fixture 설명](./fixtures/README.md)을 참고합니다.

## 실행 확인

2026-11-09에 실제 dev 서버에서 TC-ADM-NOTICE-001~007을 분할 실행해 모두 통과했습니다. 예약 전 비공개·예약 후 자동 공개, 이미지 순서와 생성된 썸네일, 실제 MP4의 CDN 재생까지 확인했습니다. E2E 타입 검사와 프로젝트 린트도 통과했습니다.

같은 날 선택형 필터를 즉시 반영하도록 변경한 뒤 로그인 setup과 조회 TC 001~003·008의 5개 테스트를 다시 실행해 모두 통과했습니다. TC 008은 날짜·정렬 조합과 날짜 해제 시 정렬·미적용 검색어 보존을 실제 dev 데이터로 확인합니다.

생성 플래그 없이 실행하면 작성 TC 004~007은 모두 건너뜁니다. 위 통과 결과는 API/CDN과 브라우저 미디어 검증 범위이며, 유저단 앱 전체 화면 검증을 의미하지 않습니다.
