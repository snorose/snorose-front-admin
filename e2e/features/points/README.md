# 포인트 E2E 테스트

## 단일건 지급·차감

포인트 테스트만 실행하려면 다음 명령을 사용합니다.

```bash
npx playwright test e2e/features/points/points.read.spec.ts --project=dev-read
npx playwright test e2e/features/points/points.write.spec.ts --project=dev-write
```

브라우저 창에서 포인트 조회 테스트의 동작을 천천히 보려면 다음 명령을 사용합니다.

```bash
E2E_SLOW_MO=500 npm run test:e2e:headed -- e2e/features/points/points.read.spec.ts
```

`--headed`는 실제 브라우저 창을 표시합니다. 테스트가 끝나면 창이 닫히며, 동영상 파일을 저장하는 기능은 아닙니다.

- read: 입력 안내, 자동 지급량, 초기화, 로그인 계정 검색, 지급·차감 확인창과 취소를 검증합니다. 실제 지급은 하지 않습니다.
- write: 별도 QA 회원에게 10포인트를 지급하고 10포인트를 차감하여 API로 잔액을 확인합니다.
- `.env.e2e.local`의 `E2E_QA_POINT_LOGIN_ID`에 별도 dev 테스트 회원 아이디를 입력합니다. 로그인에 사용하는 `E2E_ADMIN_LOGIN_ID`와 달라야 합니다. 테스트 회원 비밀번호는 필요하지 않습니다.
- 실패 시 fixture가 원래 잔액으로 복구를 시도합니다. 예상 증감 범위(10포인트)를 벗어나면 다른 변경을 덮어쓰지 않도록 복구를 중단하고 실패 처리합니다.
- 잔액을 복구해도 지급·차감 내역은 남습니다. 회원의 포인트 내역 화면은 현재 샘플 데이터를 사용하므로 실제 내역은 이 테스트의 검증 대상에 포함하지 않습니다.
- 실행 중에는 같은 QA 회원의 포인트를 다른 작업에서 변경하지 않습니다. 프로세스 강제 종료 시 복구가 실행되지 않을 수 있으므로 잔액을 확인합니다.

## 미지급 일정 관리

저장소 루트에서 실행합니다.

```bash
npx playwright test e2e/features/points/point-freeze.read.spec.ts --project=dev-read
npx playwright test e2e/features/points/point-freeze.write.spec.ts --project=dev-write
E2E_SLOW_MO=500 npm run test:e2e:headed -- e2e/features/points/point-freeze.read.spec.ts
```

추가 QA 환경변수는 필요하지 않습니다. 기존 dev 어드민 계정으로 로그인합니다.

| TC            | 검증 내용                                            |
| ------------- | ---------------------------------------------------- |
| TC-ADM-PF-001 | 실제 API 목록과 표의 항목 수·제목·열 표시            |
| TC-ADM-PF-002 | 제목 누락 시 필수 입력 안내                          |
| TC-ADM-PF-003 | 시작 날짜 누락 시 필수 입력 안내                     |
| TC-ADM-PF-004 | 종료 날짜 누락 시 필수 입력 안내                     |
| TC-ADM-PF-005 | 제목·날짜·시간 초기화                                |
| TC-ADM-PF-006 | 실제 등록·수정·삭제, 수정·삭제 취소, API 데이터 확인 |
| TC-ADM-PF-007 | 시작일이 종료일보다 늦으면 서버가 등록 거절          |

### 데이터 정리

- 변경 테스트는 다음 달 10~11일의 미래 일정을 사용합니다. 날짜 역순 검증은 11~10일을 입력합니다.
- 제목은 실행마다 고유한 `[E2E:POINT-FREEZE:<실행 ID>]` 접두사를 사용합니다. 수정 시에도 이 접두사를 유지합니다.
- fixture는 성공·실패에 관계없이 해당 실행의 접두사로 시작하는 일정만 찾아 삭제하고, 삭제 후 남은 일정이 없는지 확인합니다. 기존 일정은 수정하거나 삭제하지 않습니다.
- 프로세스를 강제로 종료하면 정리 단계가 실행되지 않을 수 있습니다. 해당 실행의 QA 일정이 남아 있는지 확인하고 정리합니다. 다음 실행이 이전 실행의 일정을 자동으로 삭제하지는 않습니다.

### 최근 검증 결과

로그인, 조회 TC 5개와 날짜 역순 TC는 통과했습니다. 정상 일정 등록 TC는 dev API의 `POST /v1/admin/points/point-freeze`가 `401`과 `인증되지 않은 유저입니다.`를 반환해 실패했습니다. 이 실행에서 수정·삭제는 검증하지 못했습니다. 인증·권한 또는 dev API 상태를 확인한 후 변경 테스트를 다시 실행해야 합니다.

설치와 공통 실행 환경은 [공통 가이드](../../../docs/playwright-e2e-guide.md)를 참고합니다. 명령은 저장소 루트에서 실행합니다.
