# 문의 및 신고 어드민 핵심 QA TC

## 수행 기준

- 대상 화면: `문의 및 신고` 어드민 페이지 (`/report/inquiry`)
- 아래 26개 TC는 릴리스 전 필수로 수행할 핵심 흐름만 포함
- 각 TC의 수행 결과는 하단 표의 `실제 결과`, `통과 여부`, `비고`, `확인` 컬럼에 기록
- 모든 자동화는 실제 로그인, dev API, dev DB를 사용
- 조회 TC 20개는 `dev-read`, 상태·댓글 변경 TC 6개는 `dev-write`에서 실행
- write TC가 생성한 데이터는 `[E2E:<runId>]`로 식별하고 테스트 종료 시 삭제·원상 복구

## Playwright 실행 정보

- 최종 실행일: `2026-08-22`
- 실행 환경: Chromium headless, `http://localhost:5173`
- 자동화 구현: `26/26` (`dev-read` 20개 + `dev-write` 6개)
- 정적 검증: E2E TypeScript 및 ESLint 통과

## 실행 방법

```bash
# 실제 dev API 기반 26개 TC 실행 (read 20 + write 6)
npm run test:e2e

# 조회 전용 20개 실행
npm run test:e2e:read

# 상태·댓글 변경 6개 실행 후 테스트 데이터 복구
npm run test:e2e:write

# Playwright UI 앱에서 실제 dev 테스트를 선택·관찰 실행
npm run test:e2e:ui

# 마지막 HTML 결과 열기
npm run test:e2e:report
```

## 실서버 수동 QA용 최소 준비 데이터

- `.env.e2e.local`의 어드민 계정과 고정 QA ID 2개
- `E2E_QA_INQUIRY_ID`: 첨부·공개 최상위 댓글이 있고 상태 변경과 댓글 CRUD가 가능한 문의
- 고정 문의의 댓글 첫 페이지에는 새 댓글이 노출될 수 있는 여유가 있어야 함
- `E2E_QA_REPORT_ID`: 상세와 신고글 원문 링크가 정상인 신고
- 게시글·족보·댓글·이용자 신고 유형별 데이터와 탈퇴 작성자 데이터
- 페이지네이션 확인을 위한 11건 이상의 데이터
