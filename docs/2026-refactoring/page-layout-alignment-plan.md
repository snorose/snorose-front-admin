# 회원·게시글·댓글·시험후기 관리 페이지 레이아웃 개선 계획

- 작성일: 2026-10-10
- 상태: 3단계 완료 / 전체 회귀 점검 전
- 목적: 시험후기·포인트 관리처럼 페이지 제목이 먼저 보이고, 그 아래에 검색·목록·상세 콘텐츠가 자연스럽게 이어지도록 구성한다.
- 산출물: 작업 범위·단계 계획과 단계별 적용·검증 결과.

## 1. 현재 구조와 개선 방향

회원 관리, 게시글 관리, 댓글 관리 모두 이미 공용 `PageHeader`를 사용한다. 1단계 화면 비교에서도 제목과 첫 콘텐츠 사이의 24px 간격은 일치했다. 따라서 **제목 아래의 콘텐츠 구조와 시각적 위계를 정리하는 작업**에 집중한다. 비교 결과와 확정한 수정 기준은 아래 1단계 결과에 정리했다.

| 화면                  | 현재 구조                                                                                 | 개선할 부분                                                                       |
| --------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 시험후기 관리         | `PageHeader` → 검색·목록 묶음 → 선택한 후기 상세                                          | 제목과 콘텐츠가 구분되는 기준 화면으로 사용한다. 검색·목록 묶음 내부는 `gap-2`다. |
| 개별·전체 포인트 관리 | `PageHeader` → 검색 또는 안내 → 정보·입력 섹션 → 작업 버튼                                | 페이지 전체 `gap-6`과 기능별 섹션 구성을 기준으로 삼는다.                         |
| 회원 관리 목록        | `PageHeader` → 큰 카드 안에 다시 ‘회원 관리’ 제목 → 검색·필터·작업 버튼·목록·페이지네이션 | 반복 제목과 카드의 추가 들여쓰기를 제거하고, 검색 영역과 결과 영역을 분리한다.    |
| 게시글 관리 목록      | `PageHeader` → 검색/필터 카드 → 별도 구분선 → 목록                                        | 검색 카드의 테두리·배경·패딩과 별도 구분선 때문에 생기는 단계 차이를 정리한다.    |
| 댓글 관리 목록        | `PageHeader` → 검색/필터 카드 → 목록                                                      | 게시글 관리와 동일한 콘텐츠 구조를 적용한다.                                      |

확인한 주요 파일:

- 기준: [시험후기 관리](../../src/pages/reviews/ExamReviewPage.tsx), [개별 포인트 관리](../../src/pages/points/AdjustSinglePointPage.tsx), [전체 포인트 관리](../../src/pages/points/AdjustAllMemberPointPage.tsx)
- 제목: [PageHeader](../../src/shared/components/PageHeader.tsx)
- 공통 바깥 여백: [App](../../src/App.tsx)의 `main` (`px-6 py-5`)

## 2. 적용할 레이아웃 기준

### 제목과 콘텐츠

1. 페이지 최상단에 `PageHeader`를 한 번 표시한다. 기존 제목과 설명을 유지한다.
2. 페이지 루트는 기존 기준인 `flex w-full flex-col gap-6`을 유지한다.
3. 회원·게시글·댓글·시험후기 모두 검색·목록 섹션 사이에 24px 간격을 둔다.
4. 바깥 여백은 `App.tsx`에서 담당한다. 페이지 제목과 섹션 제목의 왼쪽 시작 위치를 맞추고, 각 검색 입력 영역에는 포인트 관리와 같은 `rounded-md border p-4 pb-5`를 적용한다.
5. 각 페이지의 ‘검색’과 ‘목록’ 제목은 `text-lg font-bold`로 표시하고 제목과 본문 사이 간격은 4px로 둔다. 회원·시험후기의 입력 라벨은 `sr-only`로 숨기고 연결된 접근성 이름을 유지한다.
6. 테이블 자체의 테두리, 행 스타일, 상태 표시는 유지한다. 페이지 전체를 감싼 외곽 카드와 별도 구분선은 제거한다.

회원·시험후기 목록의 최종 구조:

```text
페이지 제목 (h1)·설명
  ↓ 24px
회원/시험후기 검색 (h2)
  ↓ 4px
기존 전체 폭의 테두리 검색 영역
  입력·필터 (화면에서는 placeholder·버튼 문구로 구분)
  오른쪽 하단 초기화·검색 버튼
  ↓ 24px
회원/시험후기 목록 (h2)
  기존 작업 영역·결과 수·테이블·페이지네이션
```

게시글·댓글 목록의 구조:

```text
페이지 제목 (h1)·설명
  ↓ 24px
게시글/댓글 검색 (h2)
  ↓ 4px
테두리 입력 영역 (p-4, pb-5)
  작성 시작일·작성 종료일
  게시자·게시글/댓글 검색·정렬·필터
  ↓ 16px
오른쪽 정렬된 초기화·검색 버튼
  ↓ 24px
게시글/댓글 목록 (h2)
  ↓ 4px
기존 작업 버튼·결과 수·테이블·페이지네이션
```

검색 항목의 내부 간격과 배치는 필요한 부분만 조정한다. 각 화면의 검색 조건이나 버튼 기능까지 똑같이 만들지는 않는다. 결과 수·선택 상태는 기존 데이터를 사용하고, 새로 표시하기 위해 API 호출을 추가하지 않는다.

### 좁은 화면과 긴 목록

- 검색 입력과 필터는 화면 폭에 따라 줄바꿈한다. 검색·초기화 버튼이 입력 영역을 밀어내거나 화면 밖으로 나가지 않게 한다.
- 긴 테이블은 기존 `Table`의 내부 `overflow-x-auto`를 유지한다. 1단계에서 제목·검색 영역의 가로 넘침은 없었다. 재배치하는 검색·목록 콘텐츠 래퍼에 `min-w-0`을 적용하고 기존 스크롤 래퍼를 중첩해서 추가하지 않는다.
- 게시글·댓글의 기존 `pb-12`는 제거하고 공통 `main`의 하단 20px 여백을 사용한다. 회원 목록의 외곽 카드 하단 패딩도 제거한다. 페이지네이션 자체의 `py-2`는 유지하며, 구현 후 화면 맨 아래에서 접근성과 여백을 다시 확인한다.
- 게시글·댓글 검색 패널의 내부 간격은 최종 요청에 따라 `gap-2`로 줄인다. 날짜·검색·정렬·게시판·상태 필터의 기능과 기존 반응형 배치는 유지한다.
- 새 공용 페이지 래퍼는 우선 만들지 않는다. 기존 `PageHeader`와 페이지별 구조를 활용하며, 실제 반복이 확인될 때 별도 공용화 작업을 검토한다.

회원 목록 컴포넌트의 큰 JSX를 나누어야 한다면 같은 도메인 안에서 검색 영역과 결과 영역을 분리한다. 레이아웃 정리만으로 충분하면 새 파일은 만들지 않는다.

### 연관 확인 범위: 상세 화면

상세 화면의 본격적인 재배치는 후속 작업으로 분리한다. 이번에는 목록 변경으로 인한 영향과 제목 위계만 확인한다.

| 대상                                      | 이번 작업에서 확인할 내용                                                                                     | 후속 작업 후보                                                                  |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 회원 상세 `/member/info/:encryptedUserId` | 목록과 같은 `MemberInfoPage`를 사용하므로, 목록 전용 스타일 변경이 상세·로딩 화면에 적용되지 않는지 확인한다. | 회원 상세 제목 구분과 정보 카드의 전체 스타일 정리                              |
| 게시글 상세 `/posts/manage/:postId`       | 게시글·댓글 목록에서의 진입과 뒤로가기 동작을 확인한다.                                                       | `PageHeader` 추가, 로딩·오류 상태에서도 제목 유지, 뒤로가기·원문 보기 배치 정리 |

게시글 상세는 현재 `PageHeader`가 없고 로딩·오류 상태에서 별도 화면을 반환한다. 목록과 함께 수정하면 상태별 렌더링 변경까지 포함되므로 후속 범위로 둔다.

### 제외 범위

- 포인트 관리 페이지의 구현 변경: 비교 기준으로 사용한다. 시험후기 관리는 추가 요청에 따라 검색·목록 레이아웃을 변경 범위에 포함한다.
- 회원 경고 및 강등 관리, 문의·신고, 운영·알림 페이지의 재설계

- API, 검색 파라미터, URL 동기화, 쿼리 키, 저장·삭제·제재 처리 변경

- 테이블 컬럼·표시 정보·정렬 정책 변경

- [x] 제목과 첫 콘텐츠의 시작 위치, 검색 영역의 높이, 결과 영역의 간격을 비교한다.

- [x] 기존 테스트와 사용 흐름을 확인하고 `pb-12` 등 실제 조정할 스타일을 확정한다.

#### 1단계 결과

로컬 앱에서 데스크톱 1440 × 1000과 좁은 화면 390 × 1000을 비교했다. 목록은 개인정보 없는 가상 응답으로 12행·총 36건·3페이지를 표시했고, 개별 포인트는 회원 검색 전 상태로 확인했다. 실제 API 동작 검증은 포함하지 않았다.

| 확인 항목                    | 결과                                                                                               | 수정 기준                                                                                |
| ---------------------------- | -------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 제목과 첫 콘텐츠 간격        | 모든 화면에서 24px로 일치                                                                          | 기존 `PageHeader`, 페이지 루트 `gap-6`, 공통 바깥 여백 유지                              |
| 검색 영역 시작 위치          | 기준 화면은 제목과 일치. 회원·게시글·댓글은 카드 테두리와 패딩 때문에 25px 들여쓰기                | 외곽 카드의 테두리·패딩·그림자 제거. 테이블 자체 스타일 유지                             |

검색 항목 수가 다르므로 검색 영역의 높이를 동일하게 맞추지는 않는다. 제목·검색·결과의 위계와 바깥 정렬, 섹션 간격을 통일한다. 결과 수와 선택 상태는 기존 데이터를 사용한다. 중간 제목의 표시 기준은 2단계 재점검 결과를 반영해 접근성 이름만 제공하도록 조정했다.

검증 결과:

### 추가 요청: 기본 검색 라벨과 접이식 상세 필터

- [x] 회원·시험후기·게시글·댓글에 공용 `AdvancedSearchFilters`를 적용한다.
- [x] 기본 검색에 짧은 라벨을 표시한다. 회원은 ‘회원 검색어’, 나머지 세 화면은 ‘검색어’·‘작성자’·‘작성 기간’으로 구분한다.
- [x] 작성 기간은 시작일·종료일을 하나의 `fieldset`과 `legend`로 묶고 날짜 사이 `~`와 개별 입력의 접근성 이름은 유지한다.
- [x] 회원의 등급·입학연도·전공, 시험후기의 정렬·강의 연도·시험 종류·확인 상태·논의 여부·관리 상태·신고 여부, 게시글·댓글의 정렬·의심 키워드·게시판·상태 및 게시글의 공지 옵션을 상세 필터로 이동한다.
- [x] 상세 필터는 조건이 없으면 접힌 상태로 표시하고, 적용된 조건이 있으면 ‘상세 필터 · N개 적용’으로 표시하며 자동으로 펼친다.
- [x] 적용 개수는 조건 종류별로 계산하고 기본 검색어·작성 기간·기본 정렬은 제외한다. ‘미확인’·‘의심 키워드 없음’처럼 `false`인 조건도 포함한다. 검색 버튼 방식의 페이지는 실제 적용된 조건으로, 회원은 즉시 적용되는 선택값으로 계산한다.
- [x] 상세 필터를 접어도 입력 중인 조건을 검색에 유지하고, 초기화 시 상세 조건을 해제한다.
- [x] 라벨과 입력 사이 `gap-1`, 내용 내부와 버튼 내부 `gap-2`, 필터 묶음과 버튼 묶음 사이 `gap-4`, 검색·목록 섹션 사이 `gap-6`을 유지한다.

이 구성은 앞 단계의 라벨 숨김 기준을 대체한다. 기본 입력창은 가로 배치와 반응형 줄바꿈을 유지하고, 상세 필터 안에서는 각 필터의 라벨을 표시한다. 기존 공용 `Collapsible`과 `Button`을 사용하며 새 캡처는 생성하지 않는다.

검증: 상세 필터의 기본 접힘·키보드 펼치기·접기·접힌 상태의 조건 보존·기존 적용 조건 자동 펼치기와 개수 표시를 확인한다. 기존 검색 패널 테스트에 접기 이후 검색과 자동 펼치기 검증을 추가했다. 관련 26개 파일·120개 테스트와 빌드·린트가 통과했다. 1440px·768px·390px에서 네 페이지의 펼치기·접기, 라벨·기간 묶음, 입력·버튼 넘침 없음, 검색·초기화·목록 동작을 가상 API 응답으로 확인했다. 게시글·댓글·시험후기는 URL 조건 복원 시 적용 개수와 자동 펼치기도 확인했다. 새 캡처 없이 결과만 기록했다.
