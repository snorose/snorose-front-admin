# 회원·게시글·댓글 관리 페이지 레이아웃 개선 계획

- 작성일: 2026-10-10
- 상태: 계획 작성 완료 / 구현 전
- 목적: 시험후기·포인트 관리처럼 페이지 제목이 먼저 보이고, 그 아래에 검색·목록·상세 콘텐츠가 자연스럽게 이어지도록 구성한다.
- 이번 산출물: 작업 범위와 단계 문서. 화면 코드는 이 단계에서 수정하지 않는다.

## 1. 현재 구조와 개선 방향

코드 기준으로 회원 관리, 게시글 관리, 댓글 관리 모두 이미 공용 `PageHeader`를 사용한다. 따라서 제목을 새로 추가하는 작업보다는 **제목 아래의 콘텐츠 구조와 시각적 위계를 정리하는 작업**이 필요하다. 실제 화면 비교는 구현 첫 단계에서 진행한다.

| 화면                  | 현재 구조                                                                                 | 개선할 부분                                                                       |
| --------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 시험후기 관리         | `PageHeader` → 검색·목록 묶음 → 선택한 후기 상세                                          | 제목과 콘텐츠가 구분되는 기준 화면으로 사용한다. 검색·목록 묶음 내부는 `gap-2`다. |
| 개별·전체 포인트 관리 | `PageHeader` → 검색 또는 안내 → 정보·입력 섹션 → 작업 버튼                                | 페이지 전체 `gap-6`과 기능별 섹션 구성을 기준으로 삼는다.                         |
| 회원 관리 목록        | `PageHeader` → 큰 카드 안에 다시 ‘회원 관리’ 제목 → 검색·필터·작업 버튼·목록·페이지네이션 | 반복 제목과 카드의 추가 들여쓰기를 제거하고, 검색 영역과 결과 영역을 분리한다.    |
| 게시글 관리 목록      | `PageHeader` → 검색/필터 카드 → 별도 구분선 → 목록                                        | 검색 카드의 테두리·배경·패딩과 별도 구분선 때문에 생기는 단계 차이를 정리한다.    |
| 댓글 관리 목록        | `PageHeader` → 검색/필터 카드 → 목록                                                      | 게시글 관리와 동일한 콘텐츠 구조를 적용한다.                                      |

확인한 주요 파일:

- 기준: [시험후기 관리](../../src/pages/reviews/ExamReviewPage.tsx), [개별 포인트 관리](../../src/pages/points/AdjustSinglePointPage.tsx), [전체 포인트 관리](../../src/pages/points/AdjustAllMemberPointPage.tsx)
- 제목: [PageHeader](../../src/shared/components/PageHeader.tsx)
- 공통 바깥 여백: [App](../../src/App.tsx)의 `main` (`px-6 py-5`)

## 2. 적용할 레이아웃 기준

### 제목과 콘텐츠

1. 페이지 최상단에 `PageHeader`를 한 번 표시한다. 기존 제목과 설명을 유지한다.
2. 페이지 루트는 기존 기준인 `flex w-full flex-col gap-6`을 유지한다.
3. 제목 다음에 하나의 검색·목록 콘텐츠 묶음을 두고, 묶음 내부는 `gap-4`로 통일한다. 시험후기의 `gap-2`를 그대로 복사하지 않고, 세 관리 화면의 검색 조건 수와 작업 버튼 공간을 고려한다.
4. 바깥 여백은 `App.tsx`에서 담당한다. 콘텐츠 전체에 다시 `p-6`을 적용해 제목과 본문 시작 위치가 어긋나지 않게 한다.
5. 페이지 제목을 반복하는 내부 제목은 제거한다. 필요한 섹션 제목은 ‘검색 조건’, ‘조회 결과’처럼 역할을 드러내고 `h2`로 표시한다.
6. 본문 전체를 감싼 장식용 카드 대신 검색·목록의 간격으로 구분한다. 테이블 자체의 테두리, 행 스타일, 상태 표시는 유지한다.

목록 화면의 목표 구조:

```text
페이지 제목 (h1)
페이지 설명
  ↓ 24px
콘텐츠 묶음
  검색 조건 (h2)
  검색 입력·필터·검색/초기화 버튼
  ↓ 16px
  조회 결과 (h2)
  기존 작업 버튼·결과 수·선택 상태
  테이블
  페이지네이션
```

검색 항목의 내부 간격과 배치는 필요한 부분만 조정한다. 세 화면의 검색 조건이나 버튼 기능까지 똑같이 만들지는 않는다. 결과 수·선택 상태는 기존 데이터를 사용하고, 새로 표시하기 위해 API 호출을 추가하지 않는다.

### 좁은 화면과 긴 목록

- 검색 입력과 필터는 화면 폭에 따라 줄바꿈한다. 검색·초기화 버튼이 입력 영역을 밀어내거나 화면 밖으로 나가지 않게 한다.
- 긴 테이블은 테이블 영역 안에서 가로 스크롤한다. 제목과 검색 영역까지 함께 가로 스크롤되지 않도록 필요한 래퍼에 `min-w-0`을 적용한다.
- 화면 전체의 하단 여백은 공통 기준으로 비교한다. 게시글·댓글의 기존 `pb-12`는 실제 페이지네이션과 스크롤 확인 후 통일 여부를 결정한다.
- 새 공용 페이지 래퍼는 우선 만들지 않는다. 기존 `PageHeader`와 페이지별 구조를 활용하며, 실제 반복이 확인될 때 별도 공용화 작업을 검토한다.

## 3. 작업 범위

### 필수 범위: 세 목록 화면

| 대상                        | 변경 파일                                                                                             | 구체적인 변경                                                                                                                                                                                                        |
| --------------------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 회원 관리 `/member/info`    | `src/pages/member/MemberInfoPage.tsx`, `src/domains/MemberInfo/components/MemberDirectorySection.tsx` | 상단 `PageHeader` 유지. 목록의 큰 카드와 내부 ‘회원 관리’ 제목·아이콘을 제거한다. 검색·필터와 결과·테이블을 별도 섹션으로 배치한다. 카드 제거로 불필요해지는 `mt-6`, 바깥 `p-6`, 그림자·큰 모서리 스타일을 정리한다. |
| 회원 목록 작업 영역         | `src/domains/MemberInfo/components/MemberDirectoryActionBar.tsx`                                      | 기존 위치를 조회 결과 영역으로 옮기며 줄바꿈·정렬만 필요한 만큼 조정한다. 버튼 종류와 연결 동작은 유지한다.                                                                                                          |
| 게시글 관리 `/posts/manage` | `src/pages/posts/PostManagePage.tsx`, `src/domains/Posts/components/PostFilterPanel.tsx`              | 제목 아래 검색·목록을 하나의 콘텐츠 묶음으로 구성한다. 검색 패널의 외곽 카드 스타일과 페이지의 별도 구분선을 제거한다. ‘검색 / 필터’를 검색 조건 섹션 제목으로 정리한다.                                             |
| 댓글 관리 `/posts/comments` | `src/pages/posts/PostCommentPage.tsx`, `src/domains/Comments/components/CommentFilterPanel.tsx`       | 게시글과 같은 검색·목록 구조를 적용하고 검색 카드의 외곽 스타일을 정리한다. 기존 필터와 다중 선택 기능은 유지한다.                                                                                                   |
| 게시글·댓글 결과 영역       | `src/domains/Posts/components/PostTable.tsx`, `src/domains/Comments/components/CommentTable.tsx`      | 결과 제목·작업 영역과 주변 간격, 가로 스크롤 래퍼만 필요한 만큼 조정한다. 컬럼·행 높이·행 데이터·선택 로직은 유지한다.                                                                                               |

회원 목록 컴포넌트의 큰 JSX를 나누어야 한다면 같은 도메인 안에서 검색 영역과 결과 영역을 분리한다. 레이아웃 정리만으로 충분하면 새 파일은 만들지 않는다.

### 연관 확인 범위: 상세 화면

상세 화면의 본격적인 재배치는 후속 작업으로 분리한다. 이번에는 목록 변경으로 인한 영향과 제목 위계만 확인한다.

| 대상                                      | 이번 작업에서 확인할 내용                                                                                     | 후속 작업 후보                                                                  |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 회원 상세 `/member/info/:encryptedUserId` | 목록과 같은 `MemberInfoPage`를 사용하므로, 목록 전용 스타일 변경이 상세·로딩 화면에 적용되지 않는지 확인한다. | 회원 상세 제목 구분과 정보 카드의 전체 스타일 정리                              |
| 게시글 상세 `/posts/manage/:postId`       | 게시글·댓글 목록에서의 진입과 뒤로가기 동작을 확인한다.                                                       | `PageHeader` 추가, 로딩·오류 상태에서도 제목 유지, 뒤로가기·원문 보기 배치 정리 |

게시글 상세는 현재 `PageHeader`가 없고 로딩·오류 상태에서 별도 화면을 반환한다. 목록과 함께 수정하면 상태별 렌더링 변경까지 포함되므로 후속 범위로 둔다.

### 제외 범위

- 시험후기·포인트 관리 페이지의 구현 변경: 비교 기준으로 사용한다.
- 회원 경고 및 강등 관리, 문의·신고, 운영·알림 페이지의 재설계
- 사이드바, 전역 헤더, 라우팅, `App.tsx`의 공통 여백 변경
- API, 검색 파라미터, URL 동기화, 쿼리 키, 저장·삭제·제재 처리 변경
- Input·Select·Button·Pagination 등의 공용 컴포넌트 재설계
- 테이블 컬럼·표시 정보·정렬 정책 변경

## 4. 작업 단계

### 1단계: 화면 비교와 기준 확정

- [ ] 시험후기·개별 포인트와 세 목록 화면을 같은 화면 폭에서 캡처한다.
- [ ] 제목과 첫 콘텐츠의 시작 위치, 검색 영역의 높이, 결과 영역의 간격을 비교한다.
- [ ] 데스크톱과 좁은 화면에서 콘텐츠 넘침 및 현재 스크롤 위치를 확인한다.
- [ ] 기존 테스트와 사용 흐름을 확인하고 `pb-12` 등 실제 조정할 스타일을 확정한다.

산출물: 변경 전 화면 기록과 수정할 스타일 목록.

### 2단계: 회원 관리 목록 정리

- [ ] 공용 제목 아래의 반복 제목과 큰 외곽 카드를 제거한다.
- [ ] 검색 조건과 조회 결과를 분리하고 간격·시작 위치를 맞춘다.
- [ ] 기존 작업 버튼, 총 회원 수, 테이블, 페이지네이션을 결과 영역에 배치한다.
- [ ] 목록 검색·정렬·선택·초기화와 회원 상세 진입·복귀를 확인한다.

산출물: 제목 → 검색 조건 → 조회 결과 구조를 적용한 회원 목록.

### 3단계: 게시글·댓글 목록 정리

- [ ] 두 페이지에 같은 검색·목록 콘텐츠 묶음을 적용한다.
- [ ] 검색 패널의 외곽 카드 스타일과 게시글 페이지의 구분선을 정리한다.
- [ ] 검색 섹션 제목과 결과 영역 간격을 맞춘다.
- [ ] 게시글·댓글별 검색 조건, 결과 수, 선택 작업과 페이지네이션을 유지한다.
- [ ] 긴 테이블의 가로 스크롤과 필터·버튼 줄바꿈을 확인한다.

산출물: 회원 목록과 동일한 제목·본문 위계를 가진 게시글·댓글 목록.

### 4단계: 회귀 확인과 문서 갱신

- [ ] 변경 전후 화면을 같은 폭에서 비교한다.
- [ ] 검색 버튼·Enter 검색·초기화·페이지 이동·URL 복원·뒤로가기를 확인한다.
- [ ] 로딩·빈 결과·오류·행 선택 상태에서 레이아웃을 확인한다.
- [ ] 레이블 연결, 제목 위계, 키보드 포커스와 비활성 상태를 확인한다.
- [ ] 관련 기존 테스트를 실행하고 타입 검사·빌드·린트를 확인한다. 저장소 전체 검사에서 기존 오류가 나오면 변경으로 발생한 오류와 구분해 기록한다.
- [ ] 체크리스트와 실제 변경 파일, 검증 결과를 이 문서에 반영한다.

시각적 간격 변경을 그대로 복제하는 테스트는 추가하지 않는다. 컴포넌트 분리나 조건부 렌더링 변경으로 실제 동작 위험이 생긴 부분만 필요에 따라 테스트를 보완한다.

## 5. 완료 기준

- [ ] 세 목록 화면에서 페이지 제목은 상단에 한 번 표시되고, 검색·결과는 그 아래에 배치된다.
- [ ] 제목과 본문의 바깥 시작 위치가 일치하며, 콘텐츠 전체를 감싼 중복 카드·패딩이 없다.
- [ ] 검색 조건 → 조회 결과 → 테이블 → 페이지네이션 순서와 간격이 일관된다.
- [ ] 검색·결과의 구분은 섹션 제목과 간격으로 이해할 수 있다.
- [ ] 좁은 화면에서도 입력과 버튼을 사용할 수 있고, 가로 스크롤은 테이블 영역에 한정된다.
- [ ] 기존 검색·정렬·선택·URL 복원·상세 진입·관리 작업이 유지된다.
- [ ] 회원 상세·로딩 화면과 기준으로 삼은 시험후기·포인트 화면에 영향이 없다.
- [ ] 변경 후 화면 비교와 관련 검증 결과가 기록되어 있다.
