## 2. 적용할 화면 구성

검색 섹션 제목과 테두리 영역을 유지하고, 검색 영역 안을 다음 순서로 구성한다.

```text
게시글 검색 / 댓글 검색
┌───────────────────────────────────────────────────────────────────┐
│ 검색 범위 + 검색어       작성자       작성 기간 시작일 ~ 종료일    │
│ 정렬            게시판            관리 상태            의심 키워드 │
│                                                                   │
│ 공지만 보기(게시글)                              [초기화] [검색]   │
└───────────────────────────────────────────────────────────────────┘
```

배치 기준:

- 검색 영역은 `form`, `rounded-md border p-4`, 행·열 사이 간격은 `gap-4`를 사용한다. 입력과 버튼은 36px 높이로 맞추고 그림자를 제거한다.
- 화면 전체 폭이 아닌 검색 영역의 실제 폭을 기준으로 컨테이너 쿼리를 사용한다. 사이드바가 차지하는 공간을 반영해 열 개수를 바꾼다.
- 위·아래 행은 같은 그리드와 간격을 사용한다. 영역 폭 448px 미만에서는 1열, 448px 이상에서는 2열, 1024px 이상에서는 4열이다.
- 넓은 화면에서 검색어는 2칸, 작성자와 날짜 범위는 각각 1칸을 사용한다. 아래쪽 정렬·게시판·관리 상태·의심 키워드가 같은 4열의 경계에 맞춰 정렬된다.
- 중간 폭에서는 검색어·작성자·기간이 각각 2칸 전체를 사용하고 아래 선택 필터는 2열로 배치한다. 날짜가 잘릴 정도로 기본 입력을 좁히지 않는다.
- 날짜 범위는 시작일·종료일이 가용 폭을 나누어 사용한다. `min-w-0`으로 입력과 긴 선택값의 가로 넘침을 방지한다.
- 작성자는 일반 `Input`을 사용하고 검색 범위를 설명하는 짧은 placeholder를 표시한다. 검색어 입력에는 검색 아이콘을 유지한다.
- 게시판 버튼 목록과 상태 버튼 목록을 제거하고 각각 하나의 선택 메뉴로 표시한다.
- 필드에는 보이는 레이블과 고유 id를 연결한다. 메뉴를 닫아도 선택한 조건을 트리거에서 확인할 수 있게 한다.
- 필터와 작업 영역은 구분선 없이 여백으로 구분한다. 게시글의 ‘공지만 보기’는 왼쪽, 초기화·검색은 오른쪽에 표시한다. 좁은 화면에서는 공지 조건을 별도 행으로 두고 두 버튼이 전체 폭을 균등하게 사용한다.
- 초기화는 `Button variant='outline'`, 검색은 기본 `Button type='submit'`으로 구성한다. 기존 입력 Enter 처리와 함께 사용해 한 번만 검색을 적용한다.
- ‘공지만 보기’는 shadcn 기반 공용 `Checkbox`와 연결된 `Label`을 사용한다. 체크 해제 시 `isNotice` 조건을 생략하고, 토글 중에는 조회하지 않는다.

## 3. 게시판·관리 상태 선택 규칙

### 게시글 게시판: 단일 선택

공용 `Select`를 사용한다. `BOARD_OPTIONS`를 그대로 사용하고, 맨 위에 `전체` 항목을 둔다.

- 전체: `boardId: undefined`.
- 특정 게시판: 해당 숫자 `boardId`.
- 다른 게시판을 선택하면 기존 선택을 교체한다.
- 기존 버튼은 선택한 게시판을 다시 누르면 해제하지만, 선택 메뉴에서는 `전체`를 선택해 해제한다.
- 메뉴의 문자열 값은 필터를 갱신할 때 숫자로 변환한다. `ALL` 같은 UI 전용 값은 URL·API에 전달하지 않는다.

### 댓글 게시판 / 두 화면의 관리 상태: 다중 선택

다중 선택은 공용 `Select`로 구현하지 않고, 공용 `DropdownMenu.CheckboxItem`을 조합한 `FilterMultiSelect`를 추가한다. 두 도메인에서 사용하는 작은 선택 컴포넌트로 한정한다.

- 선택이 없으면 트리거에 `전체`를 표시한다. 이는 필터 조건을 생략한다는 뜻이다.
- 하나를 선택하면 항목명을 표시한다. 여러 개를 선택하면 `게시판 2개`, `관리 상태 3개`처럼 필드명과 개수를 표시한다.
- 각 옵션은 독립적으로 선택·해제한다. 선택할 때마다 메뉴가 닫히지 않게 한다.
- 메뉴 상단에 `선택 해제`를 제공한다. 모든 옵션 값을 넣는 `전체 선택`과 조건을 생략하는 `전체`를 혼용하지 않는다.
- 마지막 항목 해제 시 빈 선택 상태로 돌아간다. 패널에서 이를 `undefined`로 매핑한다.
- 댓글 게시판은 `BOARD_OPTIONS`의 숫자 값을, 관리 상태는 `STATUS_OPTIONS`의 상태 코드를 유지한다. 표시 문자열로 API 값을 대체하지 않는다.
- 옵션은 `{ value, label }` 구조로 전달하고, `string`과 `number` 값을 지원한다. 배열을 직접 변경하지 않고 새 배열로 전달한다.
- 트리거의 레이블 연결, 항목의 선택 상태, 방향키 이동, Enter·Space 선택, Escape 닫기와 트리거로의 포커스 복귀를 확인한다.

[공용 DropdownMenu](../../src/shared/components/ui/dropdown-menu.tsx)에 체크 항목이 이미 있어 새 패키지 설치는 필요하지 않다. `ExamMultiSelect`는 시험후기 상수, 문자열 옵션, body 스크롤 제어를 포함하므로 참고 화면으로 사용한다. 시험후기에서의 공용 컴포넌트 전환은 후속 작업으로 둔다.

## 4. 검색 적용·초기화·URL 동작

필터 패널의 편집 중 상태와 URL의 적용된 검색 조건을 구분한다.

1. 검색어·날짜·선택 항목을 바꿀 때는 패널 상태만 변경한다.
2. 검색 버튼 또는 검색어·작성자 입력에서 Enter를 누르면 현재 조건을 `onFilterChange`로 전달한다. 한글 조합 중 Enter는 검색으로 처리하지 않는다.
3. 선택 메뉴와 달력 내부의 Enter는 옵션·날짜 선택에 사용한다. 패널 전체에 Enter 핸들러를 두어 검색까지 함께 실행되지 않게 한다.
4. `useManagePageUrl.handleSearchChange`가 적용한 조건을 URL에 기록하고 `page=1`로 이동한다.
5. 초기화는 게시글 `{}`, 댓글 `{ searchScope: 'CONTENT' }`를 즉시 적용하고 1페이지로 이동한다.
6. URL 진입·새로고침·이력 이동으로 조건이 바뀌면 `initialFilters`와 페이지의 `key={JSON.stringify(searchParams)}`를 통해 입력과 선택 표시를 복원한다.

값 처리 주의점:

- 의심 키워드 `false`는 명시적인 ‘없음’ 조건이다. 빈 값으로 취급하지 않는다. `전체`만 `undefined`로 처리한다.
- 게시글 `sortTypes`는 URL·패널에서는 문자열, 요청에서는 `usePostTableState`가 배열로 변환한다. 댓글 `sortTypes`는 URL·패널·요청 모두 배열이다.
- 정렬 조건이 없는 초기 화면은 최신순으로 표시한다. 현재 초기 검색·초기화가 기본 정렬 값을 반드시 요청에 넣는 방식은 아니므로, 표시 정렬을 이유로 기본 요청값을 추가하지 않는다.
- 초기 URL에 UI로 편집하지 않는 조건이 있으면 다른 필드 갱신 시 보존한다. 게시글의 `encryptedUserId`, `isVisible`, 댓글의 `isReported`가 이에 해당한다. 전체 초기화에서는 함께 해제한다.
- 댓글 `sortTypes` 배열이 여러 항목이면 기존 조건을 다른 필드 편집만으로 줄이지 않는다. 정렬을 직접 바꿀 때는 기존 UI와 동일하게 선택한 기준 하나로 교체한다.
- 날짜 문자열은 `yyyy-MM-dd`, 상태 배열과 댓글 게시판 배열은 기존 URL 직렬화 형식을 유지한다.
- 댓글의 `parentId` 진입은 일반 검색과 별도로 대댓글 조회 API를 사용한다. 검색·초기화 시 `handleSearchChange`가 새 URL을 만들어 `parentId`를 제거하고 일반 검색으로 돌아가는 현재 동작을 확인한다.

| ------------------- | --------------------------------------------------------------------- |
| 게시판 단일 선택    | 게시글에서 한 게시판만 전달하고 전체 선택 시 조건 제거                |
| 게시판 다중 선택    | 댓글에서 두 게시판 선택·개별 해제·마지막 해제 후 요청값 일치          |
| 관리 상태 다중 선택 | 두 화면에서 복수 상태 선택·개별 해제·선택 해제 및 요약 표시 일치      |
| 검색 적용 시점      | 조건 편집으로 조회하지 않고 검색 버튼·검색 입력 Enter에서 적용        |
| 키보드              | 메뉴 탐색·토글·닫기·포커스 복귀 및 IME Enter가 의도대로 동작          |
| 기존 검색           | 검색 범위별 검색어, 작성자, 공지 조건, 의심 키워드 true·false 유지    |
| 정렬·날짜           | 기존 선택지, 문자열/배열 변환, 날짜 선택·해제 유지                    |
| 초기화·페이지       | 기본값 복원, 숨은 조건 해제, 검색·초기화 후 1페이지 이동              |
| URL 복원            | 게시판·상태·false·날짜가 포함된 URL 진입과 새로고침 시 선택 표시 일치 |
| 댓글 진입 경로      | 게시글 ID 더블클릭 필터와 `parentId` 대댓글 진입, 이후 검색 복귀 정상 |
| 반응형 배치         | 1440px·768px·390px에서 레이블·트리거·날짜·버튼 겹침과 가로 넘침 없음  |

### 검증 결과

- 관련 자동 테스트: 필터 패널·공용 다중 선택·페이지 URL 연결·목록 헤더·URL 유틸리티의 6개 파일, 42개 테스트 통과.
- `npm run lint`: 통과.
- `npm run build`: TypeScript 검사와 Vite 빌드 통과. 500kB 초과 청크 안내는 남아 있다.
- 브라우저: 게시글·댓글 각각 1440px·768px·390px에서 검색 입력, 메뉴 요약, 초기화·검색 버튼 배치 확인. 필터 컨트롤의 검색 영역 이탈과 문서 가로 넘침 없음.
- 일반 검색 폼 정리 후 같은 42개 테스트와 lint·build를 재확인하고, 위 세 화면 폭에서 그리드·유동 날짜 폭·하단 구분선·모바일 버튼 배치를 다시 확인.
- 행 정렬 보완: 위·아래 그리드를 같은 4열 기준으로 맞추고 검색어에 2칸을 할당. 태블릿에서는 기본 필드에 전체 폭을 사용해 날짜 말줄임을 방지하고, 1440px·768px·390px 브라우저 확인과 lint·build 재확인.
- 공지 Checkbox 교체: 관련 3개 파일의 17개 테스트, lint·build와 TypeScript 검사 통과. 브라우저에서 레이블 클릭·Space 토글·편집 중 조회 방지·`isNotice: true` 요청·새로고침 복원·초기화 확인. jsdom에 없는 `ResizeObserver`는 테스트 공통 설정에서 대체.
- 브라우저 동작: Enter로 관리 상태 메뉴 열기, 복수 선택 중 열림 유지, Escape 닫기·포커스 복귀, 편집 중 조회 방지, 검색 Enter, 1페이지 이동, 새로고침 후 복원, 초기화 확인.
- 요청값: 브라우저가 보내는 검색 요청에서 숫자 게시판 값, 상태 코드 배열, 정렬 배열, 의심 키워드 `false`, 숨은 조건 보존 확인.
- 댓글 경로: 자동 통합 테스트에서 게시글 ID·상위 댓글 ID 더블클릭과 `parentId` 진입 후 검색·초기화의 일반 조회 복귀 확인.
- 검증 범위: 로컬 화면과 고정 API 응답으로 확인. 실제 서버의 검색 결과·필터 조합 처리는 별도 확인 대상.
