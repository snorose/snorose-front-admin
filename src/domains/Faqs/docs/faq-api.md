# FAQ 관리

## 구현 범위

- 문의 및 신고 → FAQ 관리 (`/report/faq`)
- 목록 조회, 작성, 수정, 확인 후 삭제
- 기존 공통 UI, 페이지네이션, URL 페이지 훅, API 클라이언트 재사용
- 유저 화면에 맞춘 일반 텍스트 내용 저장

## API 계약

기준: 작업 공간 `docs/admin/faq/`의 목록 조회·작성·수정·삭제 문서.

| 기능 | 요청                                   | 응답 result                |
| ---- | -------------------------------------- | -------------------------- |
| 목록 | `GET /v1/admin/support/faq?page=0`     | `{ hasNext, data: Faq[] }` |
| 작성 | `POST /v1/admin/support/faq`           | `{ faqId }`                |
| 수정 | `PATCH /v1/admin/support/faq/{faqId}`  | `{ faqId }`                |
| 삭제 | `DELETE /v1/admin/support/faq/{faqId}` | `{ faqId }`                |

작성·수정 요청은 `{ category, question, answer }`이다. 목록 분류는 `faqCategory`이며 작성자·작성일·수정일은 응답 값을 표시한다. 작성자 회원 메뉴에는 `encryptedUserId`가 필요하며, 현재 dev 응답에 없어 이름만 표시한다.

목록은 서버 응답 순서를 유지한다. 전체 페이지 정보가 없어 `hasNext`가 끝날 때까지 조회한 뒤 10개씩 표시한다. 후속 조회가 실패하면 부분 목록을 완료된 결과로 표시하지 않는다.

## 현재 UI에서 정한 사항과 확인할 사항

- 분류는 기본 6개와 기존 FAQ의 카테고리를 함께 제공한다. 드롭다운 마지막의 일반 텍스트 옵션인 `신규 카테고리 추가`에서 팝업을 열고 이름을 확인하면 바로 선택된다. FAQ 저장 시 카테고리도 함께 저장한다.
- 저장 전에 추가한 카테고리는 칩의 X로 제거할 수 있다. 제목·내용은 유지되며 다른 분류를 선택해 저장할 수 있다. 빈 이름·중복 이름·조회용 이름인 `전체`는 추가할 수 없다.
- 텍스트 검색 입력·범위·버튼은 비활성화한다. 카테고리는 선택 즉시 적용하며 URL에서 복원할 수 있다. 조건 변경 시 첫 페이지로 이동하고 펼친 행을 접는다. 초기화하면 전체 카테고리로 돌아간다.
- 화면에서는 질문·답변 대신 제목·내용으로 표시한다. 행 아래에서 내용을 펼치고 제목 열부터 작성자 열까지 사용하며, 수정·삭제 버튼은 내용 아래 오른쪽에 표시한다. 긴 제목은 접으면 말줄임하고 펼치면 전체를 표시한다.
- 분류·제목·내용의 빈 값과 공백만 있는 값은 저장하지 않는다. 내용은 일반 텍스트로 저장하며 줄바꿈을 유지한다.
- 저장 중 중복 제출과 이탈을 막고, 저장 실패 시 입력을 유지한다. 작성 중 화면을 떠날 때는 취소 확인을 제공한다.
- 작성자 정보가 제공되면 기존 회원 정보 메뉴를 사용한다. 작성자 변경 시 이전 조회 결과가 남지 않도록 갱신한다.
- 삭제는 확인 후 처리한다. 공개 여부와 순서 변경은 API 지원 전까지 제공하지 않는다. 신규 항목의 정렬 위치는 서버 기준을 따른다.

## 검증

- 단위·통합 테스트 35개: 목록·페이지 이동·입력 검증·취소·저장 실패·중복 제출·카테고리 재선택·작성자 정보 갱신
- 실제 API E2E 16개: 작성·수정·삭제, 내용 펼침, 카테고리 추가·칩 삭제·필터, 페이지 이동
- 프로덕션 빌드·린트 통과

실행 방법과 TC는 [FAQ E2E 문서](../../../../e2e/features/faqs/README.md)에서 관리한다.
