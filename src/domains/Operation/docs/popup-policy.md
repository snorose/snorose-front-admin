# 팝업 관리 정책 및 구현 가이드

## 1. 문서 목적

이 문서는 관리자 팝업 기능의 현재 구현 상태와 프론트엔드 운영 정책을 정리한다. 팝업을 등록·수정하는 관리자 화면과 실제 사용자 화면을 구현할 때 동일한 기준을 적용하는 것을 목적으로 한다.

특히 게시 기간과 노출 우선순위를 서로 다른 개념으로 정의하여, 게시 기간이 다르거나 같은 우선순위가 입력되더라도 팝업의 노출 결과가 항상 일정하도록 한다.

## 2. 용어

| 용어             | 의미                                                                   |
| ---------------- | ---------------------------------------------------------------------- |
| 게시 기간        | 팝업이 사용자 화면에 노출될 수 있는 시작일과 종료일                    |
| 상태             | 현재 날짜와 게시 기간을 비교하여 계산한 `예약`, `진행 중`, `종료` 상태 |
| 노출 우선순위    | 같은 날짜에 노출 대상이 된 팝업의 상대적인 표시 순서                   |
| 관리자 목록      | 팝업을 등록·수정·삭제하기 위한 관리자 화면의 목록                      |
| 사용자 노출 목록 | 특정 날짜에 실제 사용자에게 보여 줄 팝업 목록                          |

`노출 우선순위`는 배열의 연속된 위치를 의미하지 않는다. 예를 들어 우선순위가 `10`, `30`인 두 팝업 사이에 `20`을 추가할 수 있으며, 중간 번호가 비어 있어도 재정렬하지 않는다.

## 3. 현재 구현 상태

현재 팝업 기능은 프론트엔드 동작과 UI를 확인하기 위한 목 데이터 단계이다.

| 항목               | 현재 동작                                                                                                      |
| ------------------ | -------------------------------------------------------------------------------------------------------------- |
| 데이터 저장        | `MOCK_POPUP_CONTENTS`를 초기값으로 사용하며 브라우저 메모리에서만 변경한다. 새로고침하면 변경 내용이 사라진다. |
| 등록               | 입력값 검증 후 로컬 배열 맨 앞에 팝업을 추가한다.                                                              |
| 수정               | 같은 `id`의 로컬 데이터를 변경한다.                                                                            |
| 삭제               | 확인 모달을 거친 뒤 로컬 배열에서 제거한다.                                                                    |
| 게시 기간          | `YYYY-MM-DD` 형식의 시작일과 종료일을 입력한다.                                                                |
| 상태               | 브라우저의 현재 시각을 기준으로 `예약`, `진행 중`, `종료`를 계산한다.                                          |
| 본문               | 마크다운을 입력하고 관리자 다이얼로그에서 미리 볼 수 있다.                                                     |
| 이미지             | 파일명과 브라우저 임시 URL을 이용한 미리보기만 제공한다.                                                       |
| 노출 우선순위      | 데이터 필드, 입력, 검증과 정렬을 구현했다. 관리자 목록은 우선순위, 생성 일시, `id` 오름차순으로 표시한다.      |
| 특정 날짜 미리보기 | 이벤트 처리 코드가 주석 상태이며 구현되어 있지 않다.                                                           |

관련 코드는 다음 위치에 있다.

- `src/pages/operation/PopupManagementPage.tsx`
- `src/domains/Operation/components/PopupEditorDialog.tsx`
- `src/domains/Operation/components/PopupManagementTable.tsx`
- `src/domains/Operation/types/popup.ts`
- `src/domains/Operation/utils/validate-popup.ts`
- `src/domains/Operation/mocks/popups.ts`

## 4. 팝업 데이터 정책

### 4.1 현재 데이터

팝업은 다음 정보를 가진다.

| 필드            | 필수 여부 | 설명                                    |
| --------------- | --------- | --------------------------------------- |
| `id`            | 필수      | 팝업 식별자                             |
| `title`         | 필수      | 관리자와 사용자에게 표시할 팝업 제목    |
| `bodyMarkdown`  | 조건부    | 마크다운 형식의 본문                    |
| `imageFileName` | 조건부    | 현재 목 구현에서 사용하는 이미지 파일명 |
| `startDate`     | 필수      | 게시 시작일                             |
| `endDate`       | 필수      | 게시 종료일                             |
| `createdAt`     | 필수      | 생성 일시                               |
| `updatedAt`     | 필수      | 마지막 수정 일시                        |

본문과 이미지는 둘 중 하나 이상 반드시 입력해야 한다.

### 4.2 추가된 데이터

노출 순서를 위해 다음 필드를 추가한다.

```ts
type PopupContent = {
  // 기존 필드
  displayPriority: number;
};
```

필드 이름은 `order`보다 의미가 분명한 `displayPriority`를 사용한다.

## 5. 게시 기간과 상태 정책

### 5.1 날짜 포함 범위

게시 시작일과 종료일은 모두 노출 기간에 포함한다.

```text
startDate <= 기준 날짜 <= endDate
```

예를 들어 게시 기간이 `2026-08-01`부터 `2026-08-10`까지라면 8월 1일과 8월 10일에도 노출한다.

### 5.2 상태 계산

| 조건                             | 상태    |
| -------------------------------- | ------- |
| 기준 날짜가 게시 시작일보다 이전 | 예약    |
| 기준 날짜가 게시 기간 안에 포함  | 진행 중 |
| 기준 날짜가 게시 종료일보다 이후 | 종료    |

상태와 노출 대상은 `Asia/Seoul` 날짜를 기준으로 계산한다. 현재 구현은 브라우저 로컬 시각을 사용하므로 시간대가 다른 환경에서도 날짜 경계가 올바른지 확인해야 한다.

게시 종료일은 시작일보다 빠를 수 없다. 시작일과 종료일이 같으면 해당 날짜 하루 동안 노출하는 팝업으로 처리한다.

## 6. 콘텐츠 입력 및 검증 정책

### 6.1 필수 입력

- 제목은 공백을 제외한 값이 있어야 한다.
- 게시 시작일과 종료일을 모두 입력해야 한다.
- 본문 또는 이미지를 하나 이상 입력해야 한다.
- 저장 전에 검증하며, 실패한 경우 저장 확인 모달을 열지 않고 오류 메시지를 표시한다.

### 6.2 본문

- 본문은 최대 3,000자까지 입력할 수 있다.
- 현재 미리보기에서 허용하는 마크다운 요소는 링크, 줄바꿈, 문단, 굵은 글씨, 순서 있는 목록, 순서 없는 목록이다.
- 원시 HTML은 렌더링하지 않는다.
- 링크에는 `http`, `https`, `mailto`, `tel` 프로토콜과 내부·상대 경로 및 페이지 앵커를 사용할 수 있다.
- 허용하지 않은 프로토콜을 사용하는 링크는 저장 검증에서 거부하고 미리보기에서도 제거한다.
- 외부 HTTP 링크는 새 탭으로 열고 `noopener noreferrer`를 적용한다.

### 6.3 이미지

- 현재 허용 확장자는 `jpg`, `jpeg`, `png`, `gif`, `webp`이다.
- 현재 파일 크기, 이미지 해상도, 가로세로 비율 제한은 정해져 있지 않다.
- 관리자 미리보기에서는 브라우저 임시 URL을 사용하며, 이미지 선택·교체·삭제 상태를 화면에서 명확하게 구분한다.

## 7. 노출 우선순위 정책

### 7.1 기본 규칙

- `displayPriority`는 1 이상의 정수이다.
- 숫자가 작을수록 먼저 노출한다.
- 우선순위 숫자는 연속적일 필요가 없다.
- 같은 우선순위의 팝업을 여러 개 저장할 수 있다.
- 팝업을 추가·수정·삭제해도 다른 팝업의 우선순위를 자동으로 변경하지 않는다.
- 삭제되거나 게시가 종료되어 번호가 비더라도 나머지 번호를 당기지 않는다.

입력 화면에는 다음 안내를 표시한다.

> 숫자가 작을수록 먼저 노출됩니다. 같은 우선순위에서는 먼저 등록한 팝업이 먼저 노출됩니다.

### 7.2 사용자 노출 순서

사용자 노출 목록은 반드시 다음 순서로 결정한다.

1. 기준 날짜가 게시 기간에 포함된 팝업만 조회한다.
2. `displayPriority` 오름차순으로 정렬한다.
3. 우선순위가 같으면 `createdAt` 오름차순으로 정렬한다.
4. 생성 일시도 같으면 `id` 오름차순으로 정렬한다.

프론트엔드에서 노출 목록을 구성할 때에는 반드시 같은 필터와 보조 정렬 기준을 사용한다.

### 7.3 같은 우선순위 처리

같은 숫자가 입력되더라도 기존 팝업을 하나씩 뒤로 밀지 않는다. 동일 우선순위 안에서는 먼저 생성된 팝업을 먼저 노출하고, `id`를 마지막 기준으로 사용하여 결과가 실행할 때마다 바뀌지 않도록 한다.

예를 들어 다음 두 팝업이 모두 노출 대상이라면 A를 먼저 노출한다.

| 팝업 | 우선순위 | 생성 일시        |
| ---- | -------: | ---------------- |
| A    |       10 | 2026-08-01 09:00 |
| B    |       10 | 2026-08-02 09:00 |

우선순위를 중복할 수 없도록 하고 뒷번호를 자동으로 이동하는 방식은 정확한 배열 위치가 반드시 필요한 경우에만 검토한다. 게시 기간이 일부만 겹치는 데이터에서는 이동 대상을 일관되게 정의하기 어렵기 때문이다.

### 7.4 게시 기간이 다른 경우

노출 대상 필터링을 먼저 하므로, 게시 기간이 겹치지 않는 팝업은 같은 우선순위를 사용해도 서로 영향을 주지 않는다.

| 팝업 | 게시 기간           | 우선순위 |
| ---- | ------------------- | -------: |
| A    | 8월 1일 ~ 8월 10일  |       10 |
| B    | 8월 5일 ~ 8월 20일  |       20 |
| C    | 8월 11일 ~ 8월 30일 |       10 |

- 8월 7일 노출 순서: A, B
- 8월 12일 노출 순서: C, B

현재 노출 중인 팝업이 종료되어 우선순위 `10`이 없어지면, 우선순위 `20`인 팝업이 자동으로 첫 번째 노출 대상이 된다. 번호를 `10`으로 다시 변경할 필요는 없다.

### 7.5 신규 팝업 기본값

신규 팝업은 기존 최대 우선순위에 10을 더한 값을 기본값으로 사용한다. 팝업이 하나도 없으면 `10`을 사용한다.

```text
10, 20, 30
```

간격을 두면 기존 값을 일괄 변경하지 않고도 `15`, `25`와 같이 중간 우선순위를 지정할 수 있다. 기본값은 편의를 위한 값이며 관리자가 저장 전에 변경할 수 있다.

기존 목 데이터에는 의도한 노출 순서를 확인한 뒤 `10`, `20`, `30` 순으로 값을 부여한다. 의도한 순서를 알 수 없다면 `createdAt`, `id` 오름차순을 기준으로 부여한다.

## 8. 관리자 화면 정책

### 8.1 등록·수정 다이얼로그

숫자 입력창만 추가하는 것으로 기능이 완성되지는 않는다. 다이얼로그에는 다음 UI가 필요하다.

- `노출 우선순위` 라벨을 가진 `number` 입력
- `min=1`, `step=1` 설정
- 우선순위 규칙 안내 문구
- 빈 값, 0 이하, 소수 입력에 대한 검증 및 오류 메시지
- 신규 등록 시 계산된 기본값
- 수정 시 저장되어 있던 우선순위 표시

HTML 입력 속성은 입력 편의를 제공할 뿐이므로, 저장 함수에서도 1 이상의 정수인지 다시 검증해야 한다.

### 8.2 관리자 목록

- 목록에 `노출 우선순위` 열을 표시한다.
- 사용자에게 노출되는 순서를 확인할 수 있도록 우선순위 정렬 결과가 명확하게 보여야 한다.
- 관리자 목록에는 예약·진행 중·종료 팝업이 모두 포함될 수 있으므로, 관리자 목록의 정렬과 특정 날짜의 사용자 노출 순서를 같은 개념으로 취급하지 않는다.
- 특정 날짜 미리보기를 구현할 때에는 해당 날짜로 게시 기간을 필터링한 후 사용자 노출 정렬 규칙을 그대로 적용한다.

## 10. 필수 테스트 사례

| 사례                                      | 기대 결과                         |
| ----------------------------------------- | --------------------------------- |
| 기준 날짜가 시작일과 같음                 | 진행 중이며 노출 대상에 포함      |
| 기준 날짜가 종료일과 같음                 | 진행 중이며 노출 대상에 포함      |
| 종료일이 시작일보다 빠름                  | 저장 거부                         |
| 우선순위가 빈 값, 0, 음수 또는 소수       | 저장 거부                         |
| 서로 다른 우선순위                        | 작은 숫자가 먼저 노출             |
| 같은 우선순위                             | 생성 일시가 빠른 팝업이 먼저 노출 |
| 우선순위와 생성 일시가 같음               | `id`가 작은 팝업이 먼저 노출      |
| 같은 우선순위지만 게시 기간이 겹치지 않음 | 해당 날짜에 활성화된 팝업만 노출  |
| 중간 우선순위의 팝업 삭제                 | 나머지 우선순위를 변경하지 않음   |

## 11. 추가 결정이 필요한 항목

다음 항목은 현재 코드와 정책에서 확정되어 있지 않으므로 구현 전에 별도로 결정한다.

- 제목 최대 길이
- 이미지 최대 파일 크기, 해상도 및 가로세로 비율
- 활성 팝업의 최대 동시 노출 개수
